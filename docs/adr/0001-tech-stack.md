# ADR 0001: 第一阶段技术栈

## 状态

建议采用。

## 背景

项目第一阶段需要快速验证网页版，同时为未来微信小程序复用核心逻辑。系统不应过早拆成多个服务，也不应把业务规则写死在前端组件里。

## 决策

第一阶段采用 TypeScript 模块化单体：

- `apps/web` 使用 Next.js + React。
- `packages/core` 存放领域规则、时间处理和排期计算。
- `packages/db` 存放数据库 schema、migration 和数据库访问封装。
- `packages/api-client` 存放前端 API 调用封装。
- 数据库使用 Postgres。
- ORM 在 Drizzle 和 Prisma 之间二选一，开始建库前补充 ADR。
- 测试使用 Vitest。

## 结果

优点：

- 可以快速上线网页版。
- 核心逻辑能被 Web 和小程序复用。
- 单仓库更容易让 AI 和人类开发者理解全局。

代价：

- 需要维护包边界。
- 后续如果引入小程序构建工具，需要额外处理共享包兼容性。

## 后续检查

当出现以下情况时重新评估：

- 小程序端无法稳定复用 `packages/core`。
- API 规模明显增长，需要独立后端服务。
- 数据库访问和业务逻辑出现边界混乱。
