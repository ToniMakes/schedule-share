# ADR 0002: 时间和时区策略

## 状态

建议采用。

## 背景

本项目的核心价值是跨人群找共同空闲时间。目标用户可能分布在澳大利亚、中国大陆和其他国家。如果时间规则不统一，后续会出现难以排查的错误。

## 决策

- 所有精确时间入库时使用 UTC。
- 日程创建时必须保存组织者选择的 IANA 时区。
- 日期范围和每日时间窗口按照日程时区解释。
- 前端可按用户本地时区展示，但必须明确显示当前展示时区。
- 时间格生成、合并和结果计算全部放在 `packages/core`。
- 测试必须覆盖跨天和夏令时边界。

## 结果

优点：

- 避免数据库中混用多个本地时间。
- 支持海外版和国内版复用同一套数据。
- 更容易测试和排查。

代价：

- UI 需要清楚提示展示时区。
- 时间处理库选择会影响打包体积和小程序兼容性。

## 后续检查

开始实现前需要确定具体时间库，并补充 ADR。
