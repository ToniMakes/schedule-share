# ADR 0008: 可用时间导入与个人长期模板

## 状态

建议采用。

## 背景

当前 MVP 已经跑通匿名创建日程、匿名参与者填写可用时间、计算共同空闲时间和多数人空闲时间。下一阶段需要寻找比普通多人日程投票工具更明显的差异化。

两个高价值方向是：

- 参与者可以上传课表截图、排班截图或粘贴已有日程文本，由系统识别忙碌时间，再整理出可提交的可用时间。
- 登录用户可以维护自己的长期可用时间模板，在每次参与活动时一键导入，再按当次活动做少量修改。

这两个能力都会影响核心时间规则、隐私边界、API 契约和未来账号体系，因此需要先记录架构决策。

ADR 0009 已将这两个能力纳入更大的“多种可用时间添加方式”策略中；本 ADR 仍作为图片/文本导入和个人长期模板的细化依据。

## 决策

第一阶段将“导入”和“模板”定位为填写流程的辅助能力，而不是替代用户确认的自动提交能力。

- 匿名参与者仍然可以使用当前手动填写主流程。
- 课表图片、排班截图和文本导入用于生成建议可用时间，用户必须确认后才会提交。
- 原始上传文件默认只做临时处理，不写入数据库，不作为训练数据或广告定向数据。
- 识别结果需要包含置信度、无法确认的片段和用户可编辑的建议时间。
- 识别服务封装在 Web 服务端边界内，未来可替换 provider；`packages/core` 不调用 AI、OCR、HTTP 或文件存储。
- 忙碌时间到可用时间的转换、可用时间与日程时间格的对齐、连续时间格合并必须放在 `packages/core`。
- 个人长期模板必须依赖登录账号，但登录只服务于高频用户，不强制参与者注册。
- 个人模板保存“长期有空窗口”，不保存每个活动的提交副本；当用户进入某个活动时，系统按该活动的日期范围、时间粒度和时区生成预填建议。
- 模板导入同样只是预填，不直接代表用户已提交。

## 范围划分

### 导入 v1

支持：

- 单张课表或排班截图。
- 粘贴纯文本日程。
- 输出忙碌时间块和建议可用时间槽。
- 用户在当前活动页面确认或手动修正。

暂不支持：

- 多图批量合并。
- 邮箱、Google Calendar、Outlook、Apple Calendar 深度授权同步。
- 后台异步长任务。
- 保存原始图片供历史回看。
- 无确认自动提交。

### 个人模板 v1

支持：

- 登录用户创建一个或多个长期可用时间模板。
- 模板包含名称、时区、每周重复可用窗口和可选备注。
- 参与活动时选择一个模板，系统投影到当前活动时间范围并生成预填槽。
- 用户可在提交前增删本次活动的可用时间。

暂不支持：

- 团队共享模板。
- 复杂例外规则，例如节假日、考试周、请假。
- 多账号组织空间。
- 模板自动应用到所有未来活动。

## 架构影响

- `packages/core` 新增忙碌时间块、长期可用窗口和模板投影的纯函数。
- `packages/api-client` 新增导入预览、模板 CRUD 和模板预填预览的契约类型。
- `packages/db` 在实现个人模板前新增用户、模板和模板窗口表及 migration。
- `apps/web` 负责上传、识别结果确认、模板管理和导入交互。
- API 层必须继续做输入校验、权限校验和统一错误响应。

## 隐私与成本

- 图片和文本导入可能包含学校、课程、教室、工作地点、姓名或其他个人信息，必须在 UI 和隐私说明中明确提示。
- 默认不持久化原始上传内容。
- 只保存用户确认后的可用时间；登录模板只保存用户主动创建的长期可用窗口。
- 导入接口需要文件大小限制、频率限制和错误兜底，避免 AI/OCR 成本失控。
- 如果未来为了调试保存失败样本，必须另写 ADR，并提供明确的用户同意与保留期限。

## 结果

优点：

- 明显降低学生、兼职排班、跨时区社群用户的填写成本。
- 长期模板让轻量工具获得重复使用理由。
- 保持匿名主流程简单，不牺牲 MVP 的低门槛。
- 通过 `packages/core` 约束时间转换，减少后期功能堆叠导致的代码混乱。

代价：

- 个人模板引入账号体系和更长的数据保留周期。
- AI/OCR 识别存在不确定性，需要确认 UI 和失败兜底。
- 导入能力会增加 API 成本、安全校验和隐私说明复杂度。

## 后续检查

当出现以下情况时重新评估：

- 内测用户大量依赖模板，匿名流程不再是主入口。
- 导入成本明显高于预期。
- 中国大陆用户对 AI/OCR 服务可用性提出强需求。
- 需要微信登录、小程序端模板同步或国内模型服务。
- 需要保存原始上传文件、失败样本或用户日程历史。
