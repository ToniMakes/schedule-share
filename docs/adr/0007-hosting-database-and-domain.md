# ADR 0007: MVP 部署、数据库和域名策略

## 状态

建议采用。

## 背景

海外网页版 MVP 需要尽快进入真实环境内测，同时保持月成本尽可能低。目标用户包括海外用户和少量中国大陆用户，但第一阶段尚未准备中国内地备案、微信小程序备案、国内云部署和国内支付/广告合规链路。

项目已有 Postgres schema、migration、健康检查和 smoke test。当前主要缺口是接入真实托管 Postgres，并部署到一个可公开访问的正式地址。

## 决策

第一阶段采用以下部署策略：

- Web 应用优先部署到 Vercel。
- 数据库优先使用 Neon Postgres。
- Neon 区域优先选择 Singapore。
- 正式 Web 地址优先使用 `https://schedule.tonimakes.com`。
- `tonimakes.com/schedule` 暂不作为 MVP 首选地址，除非未来主站和日程表应用由同一部署系统托管，或明确引入反向代理/重写规则。
- 生产环境设置 `APP_BASE_URL=https://schedule.tonimakes.com`，确保分享、管理和编辑链接稳定。

## 理由

- Neon 是标准 Postgres，未来可以迁移到其他 Postgres 托管服务或国内云 RDS。
- Singapore 区域通常比 Sydney 或美国区域更适合作为兼顾海外和中国大陆访问的低成本起点。
- 中国大陆用户不会直接访问数据库，请求路径是浏览器访问 Web/API，再由服务端访问 Postgres。因此大陆可用性的主要风险在 Web/API 部署平台和域名访问链路，不在数据库是否暴露到公网。
- 子域名 `schedule.tonimakes.com` 便于独立部署、独立回滚和后续替换平台，不影响 `tonimakes.com` 主站。
- MVP 阶段先保持海外部署和低成本数据库，避免过早承担中国内地备案、国内云运维和微信小程序发布流程。

## 结果

优点：

- 可以以接近零成本启动真实环境内测。
- 数据库和部署平台接入简单，适合当前 Next.js 单体应用。
- 域名结构清楚，便于后续把主站、日程表和小程序后端分开演进。
- 保留迁移到国内云 Postgres 或单独国内 API 的空间。

代价：

- Vercel 和海外托管服务不保证中国大陆访问稳定性。
- 中国大陆访问性能不是 MVP 阶段的优化重点。
- 后续如果认真服务国内用户，仍需设计国内部署、备案、微信小程序和可能的数据同步/迁移方案。

## 后续检查

当出现以下情况时重新评估：

- 中国大陆用户成为主要用户来源。
- 需要正式发布微信小程序。
- Vercel 或 Neon 的大陆访问稳定性影响内测结论。
- 免费或低价配额不足以支撑真实使用。
- 需要把 `tonimakes.com/schedule` 作为正式入口。
