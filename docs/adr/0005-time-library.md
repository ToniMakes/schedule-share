# ADR 0005: 时间处理库

## 状态

采用。

## 背景

项目需要支持澳大利亚、中国大陆和其他地区用户共同填写日程。核心逻辑必须正确处理 IANA 时区、UTC 存储、本地日期展示、跨天窗口和夏令时边界。

直接使用 JavaScript `Date` 容易把本地时间、UTC 和时区转换混在一起，也不适合表达“某个 IANA 时区下的本地日期和本地时间”。

## 决策

核心包使用 Luxon 处理时间和时区：

- 使用 IANA 时区，例如 `Australia/Sydney`、`Asia/Shanghai`。
- 所有精确时间输出为 UTC ISO 字符串。
- 日程日期范围和每日时间窗口按日程时区解释。
- 时间格沿真实时间轴生成，因此夏令时跳时当天可能出现本地时间标签跳跃。

## 结果

优点：

- 比手写 `Date` 更容易读懂和测试。
- 对跨时区和夏令时有明确语义。
- Web 端和未来小程序端可以复用同一套核心逻辑。

代价：

- 核心包增加一个运行时依赖。
- 未来小程序端需要验证 Luxon 与目标构建工具和运行环境的兼容性。

## 后续检查

当开始微信小程序版本时，需要验证：

- 小程序构建链是否能打包 Luxon。
- 目标运行环境的 `Intl` 时区数据是否足够。
- 是否需要替换为 Temporal polyfill 或服务端时间计算。
