# 内测检查清单

## 目标

验证海外网页版 MVP 是否能支持一次真实多人日程协调：组织者创建日程，参与者填写可用时间，组织者查看结果、导出 CSV、锁定或归档日程。

## 内测前技术检查

环境变量说明见 `docs/environment.md`。

1. 设置数据库连接：

```powershell
$env:DATABASE_URL="postgres://..."
```

2. 检查数据库连接：

```powershell
corepack pnpm db:check
```

第一次迁移前如果提示缺少表，是正常状态。

3. 执行 migration：

```powershell
corepack pnpm db:migrate
```

4. 再次检查数据库：

```powershell
corepack pnpm db:check
```

5. 启动 Web 服务：

```powershell
corepack pnpm dev
```

6. 跑 API smoke test：

```powershell
corepack pnpm smoke:api
```

如果测试目标不是 `http://localhost:3000`，先设置 `SMOKE_BASE_URL`。

## 组织者手动检查

- 打开首页。
- 进入创建日程页。
- 创建一个 1 到 3 天范围的日程。
- 复制公开分享链接。
- 复制管理链接，并确认管理链接不要发给参与者。
- 打开管理页，确认参与者数、状态和全员可用时间区域能显示。
- 点击导出 CSV，确认文件能下载并能被 Excel、Numbers 或 Google Sheets 打开。
- 点击锁定，确认状态变为已锁定。
- 点击归档，确认状态变为已归档。

## 参与者手动检查

- 用公开分享链接打开日程。
- 输入昵称。
- 选择多个可用时间。
- 提交后确认页面明确提示“保存编辑链接”，并复制或保存该链接。
- 用编辑链接重新打开。
- 修改昵称或可用时间。
- 提交修改。
- 日程锁定后，再尝试提交或修改，确认页面给出不能修改的提示。

## 多人结果检查

- 至少邀请 3 人填写。
- 确认“全员可用时间”只显示所有参与者都选择的连续时间段。
- 确认“当前最优时间槽”按可用人数排序。
- 确认 CSV 导出的全员可用时间、时间槽排名和参与者列表与页面一致。

## 体验观察点

- 组织者是否能在 1 分钟内完成创建和分享。
- 参与者是否能在 30 秒内完成填写。
- 手机屏幕上是否有文字拥挤或横向滚动。
- 用户是否理解“管理链接”和“分享链接”的区别。
- 用户是否知道保存编辑链接。
- 结果页是否能一眼看出最佳时间。
