# 产品说明

## 产品定位

这是一个面向跨时区多人协调的日程共享工具。用户可以创建一个日程房间，邀请其他人通过拖拽网格、导入课表/排班、复用个人模板或选择候选时间来填写可用时间，并快速找出所有人或大多数人都方便的时间段。

第一阶段优先服务海外用户和少量国内用户，通过移动优先的网页版验证需求。微信小程序作为第二阶段入口，复用同一套后端 API 和核心业务逻辑。

多种可用时间添加方式的详细产品规格见 `docs/availability-entry-methods.md`。常驻广告、AI 图片识别成本、激励广告换额度和风控方案见 `docs/monetization.md`，真实展示广告上线执行清单见 `docs/ad-launch-checklist.md`。架构决策见 `docs/adr/0008-availability-import-and-templates.md` 和 `docs/adr/0009-multiple-availability-entry-methods.md`。

## 目标用户

- 经常组织多人会议、聚会、课程、社群活动的人。
- 海外华人、跨国家庭、留学生、远程团队和兴趣社群。
- 不想注册复杂账号，只想快速收集时间的人。

## 核心场景

1. 组织者创建日程房间，设置日期范围、每天可选时间段和时间粒度。
2. 系统生成分享链接。
3. 参与者通过链接选择一种最省事的方式填写姓名和可用时间：手动拖拽、课表/排班导入、粘贴文本、个人长期模板或候选时间投票。
4. 系统自动计算并展示共同空闲时间与多数人空闲时间。
5. 组织者复制候选时间，或锁定最终时间。

## MVP 范围

MVP 必须包含：

- 创建日程房间。
- 设置日期范围。
- 设置每天可选时间窗口。
- 设置时间粒度：15、30 或 60 分钟。
- 分享公开填写链接。
- 参与者使用昵称填写可用时间。
- 参与者可使用编辑密钥修改自己的提交。
- 展示所有人都有空的时间段。
- 展示按可用人数排序的候选时间段。
- 移动端可用。

MVP 暂不包含：

- 微信小程序。
- 支付和会员。
- 复杂团队管理。
- Google Calendar、Outlook、Apple Calendar 深度同步。
- 微信登录、邮箱登录或手机号登录。
- 自动短信、邮件或微信提醒。
- 实时协同编辑。
- 活动报名和票务。

## MVP+ 差异化方向

在当前匿名填写主链路稳定后，把产品扩展成多种可用时间添加方式：

- 手动拖拽网格：吸收 When2meet 的核心体验，参与者直接在日期 x 时间格上涂出自己有空的时间，结果页以热力图或排名展示重叠程度。
- 课表/排班导入：参与者上传一张课表、排班截图，或粘贴已有日程文本，系统识别忙碌时间并生成可编辑的可用时间建议。
- 个人长期可用模板：登录用户维护自己的长期有空时间，例如“周一到周四晚上、周末下午”。参与新的活动时，可以一键把模板投影到该活动的日期范围和时间粒度中，再按当次情况调整。
- 候选时间投票：吸收 Doodle/Rallly 的模式，由组织者列出几个具体候选时间，参与者只需要选择方便、也许或不方便。
- 文件和日历轻导入：基础 `.ics`、CSV、表格/文本粘贴导入忙碌时间和最终时间日历导出已实现；后续继续用真实样本补复杂 recurrence、特殊节次和嵌套表头。

除手动拖拽外，其他添加方式都只能作为预填辅助，不能绕过用户确认直接提交。匿名参与者仍应能不注册、不导入、不使用模板完成填写。

## 成功标准

第一版上线后，优先观察这些指标：

- 组织者能否在 1 分钟内创建并分享日程。
- 参与者能否在 30 秒内完成填写。
- 单个日程是否能支持 5 到 20 人稳定使用。
- 创建者是否会创建第二个日程。
- 用户是否愿意把链接分享到微信、WhatsApp、Telegram 或邮件。

## 产品原则

- 参与者不需要注册。
- 创建和填写流程必须短。
- 结果页必须一眼看出最佳时间。
- 海外网页版面向跨地区用户，正式推广前应提供至少中文和英文两套核心 UI 文案；导入解析支持英文时间表达不等于完整双语。
- 广告可以提供被动收入，默认每个页面都尽量保留顶部、底部、桌面侧栏或移动 anchor 等外围广告位，但不能阻断创建、填写、编辑、提交、导入预览和复制/导出等核心操作。
- AI 图片识别可以使用用户主动触发的激励广告换额度；普通常驻广告不能承诺换奖励，也不能诱导点击。
- AI 识别和个人模板只减少重复操作，不替用户做最终决定。
- 每一种添加方式最后都必须归一化为同一份可用时间数据，不能为单个入口复制业务规则。
- 支持跨时区是基础能力，不是高级功能。
- 数据、权限和保留规则宁可简单，也要明确；过期日程应有自动归档和删除策略，避免数据库无限增长。

## 后续方向

在 MVP 被真实使用后，再根据数据选择扩展方向：

- 高频组织者功能：模板、群组、导出、提醒、隐藏广告。
- 高频参与者功能：长期可用模板、课表/排班导入、历史昵称和默认时区。
- 填写方式扩展：候选时间投票、`.ics` 文件导入、CSV/表格粘贴导入、上次活动设置复用。
- 成本可控的 AI 图片识别：免费试用额度、激励广告换识别额度、全站成本护栏和失败退款。
- 默认全站外围常驻广告：创建、填写、编辑、结果、管理和说明页面都尽量保留边缘广告位；结果页、提交成功页和说明页可提高广告密度。
- 数据保留和自动清理：为匿名日程设置明确过期、归档、硬删除和人工删除请求流程，降低存储成本和隐私风险。
- 中英双语：英文已成为默认入口，公开说明页覆盖 `/`、`/about`、`/privacy`、`/contact`、`/feedback`、`/terms`，英文创建页 `/new` 复用同一表单逻辑；公开日程英文入口 `/s/:publicId` 已覆盖开放网格手动填写、图片/文本/CSV/ICS/模板预填面板、基础结果热力图、候选投票填写和候选投票结果面板；参与者英文编辑入口 `/s/:publicId/edit/:participantId` 已覆盖普通可用时间、图片/文本/CSV/ICS/模板预填面板和候选投票修改，并会在英文提交后保存英文编辑链接；组织者英文管理入口 `/s/:publicId/manage` 已覆盖分享链接、管理操作、导出、结果摘要和最终时间确认/复制；中文入口迁移到 `/zh/...`，旧 `/en/...` 保留兼容重定向。语言切换会写入本地语言偏好，当前 API 错误码已有中英文兜底。图片识别公开入口仍默认关闭，后续继续覆盖完整文案字典、深层组件文案和更广生产 smoke。
- 机构版：品牌页、多人管理、批量活动。
- 微信小程序：微信群分享、微信生态内填写体验。
- 日历集成：导入忙闲状态、导出最终时间。
